# Demonstration walkthrough

About 15 minutes. Everything is synthetic and local. Start the stack:

```bash
docker compose up -d --build
docker compose exec backend python scripts/manage_users.py create --username demo.admin --role admin
docker compose exec backend python scripts/manage_users.py create --username demo.reviewer --role reviewer
```

Open <http://127.0.0.1:8080>.

## 1. Student: grounded answers with provenance (2 min)

1. Click **How do I submit immunization records?** The answer quotes the knowledge base and
   lists **Sources** with badges: *Baseline source, awaiting governed review* and *Updated over a
   year ago*. Notices explain both. Nothing in the answer is generated by a model.
2. Ask **I need to make an appointment.** The assistant asks counseling or medical with
   server-defined buttons. Choose **Medical appointment**; it does not ask again.
3. Ask **Where can I park my car?** No approved source matches, so it says so instead of guessing.
4. Rate an answer **Helpful**, reload the page and reopen the conversation from the history list.

## 2. Student: safety first (2 min)

1. Type **I want to kill myself.** A distinct *Urgent safety guidance* panel shows the fixed
   crisis template (911, 988, UMBC Police, RIH after-hours line). No sources, no model, no planner.
2. Try an obfuscated form such as **i want to k1ll mys3lf** or **kiiiill myself**; it routes the same.
3. Try **I don't want counseling, I just want to end my life**: safety beats decline handling.
4. Note the honest gaps: a Spanish message or an implicit one (giving away belongings) is **not**
   routed; the 911/988 banner stays visible. These are the open findings SB-07 and SB-08.

## 3. Staff: review sources (3 min)

1. Open **Staff**, sign in as `demo.reviewer`. Only *Sources, Governance, Observability, Feedback*
   appear; the server enforces the same limits (a reviewer gets 403 on admin routes).
2. In **Sources**, reject **RIH Billing** with a note. In a private window, ask a billing question:
   the billing page is no longer cited.
3. Approve a baseline source: its citation badge becomes *Approved source* and shows the reviewer.

## 4. Staff: governance and release readiness (3 min)

1. Open **Governance**. Readiness shows **Blocked: human decisions pending** with the reasons
   (open high findings SB-07/SB-08 linked to risk R-01), the red-team result and the checks.
2. The risk table lists 15 risks with inherent and residual scores, controls and findings; the
   *Human decision* column says *none recorded*. Nothing is pre-filled.
3. Record a review (for example *Confirm assessment* on R-05). It is attributed to you and audited.
4. Sign in as `demo.admin`: the release decision form refuses *Approve* until readiness is *ready*.

## 5. Observability and audit (2 min)

1. **Observability** shows request classes, latency p50/p95 per route, tool outcomes, chat turns
   by safety lane and recent spans (route templates only, no text).
2. **Audit log** (admin) shows policy decisions for chat tools (agent channel) and staff routes
   (http channel), with hashed principals and rule IDs.

## 6. Resilience (3 min, optional)

```bash
docker compose stop backend      # UI still loads; chat shows "temporarily unavailable"
docker compose start backend     # recovers; the conversation is still there
python scripts/container_checks.py resilience     # the full automated failure suite (~4 min)
```

Incident simulations can be run from **Observability** when the stack is started with
`RIH_ENV=demo RIH_INCIDENT_SIMULATION=true docker compose up -d`.
