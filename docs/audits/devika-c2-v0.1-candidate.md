## Transport and common types

Prefix `/api/v1`; UTF-8 JSON; timestamps UTC RFC3339; opaque IDs generated by server.
No diagnosis/treatment/emergency-service claims. Exact OpenAPI schemas are exported
from the jointly agreed Pydantic types and checked into one versioned snapshot;
TypeScript types and API compatibility tests derive from that snapshot. Snapshot
owner is Abhinav, with Devika review; session/feedback definitions are Devika-owned
under that shared schema. Unknown request fields rejected. No raw dispatcher trace,
message text, tool arguments or exception strings in public errors or audit logs.

Candidate limits: message 4,000 characters, feedback enum only, history page size
1–50 (default 20), resource result limit 1–20 (default 10), bounded JSON bodies
64 KiB. Limits are enforced server-side; safety routing runs on the complete
accepted original message before decline/planner/retrieval/model processing.
Oversized input is rejected explicitly, never truncated and presented as screened.

`ErrorEnvelope = {error: {code, message, request_id}}`. Stable codes:
`invalid_request` (422), `unauthenticated` (401), `not_found` (404, including
non-owned sessions), `forbidden` (403 for authenticated role denial),
`rate_limited` (429), `dependency_unavailable` (503), `internal_error` (500).
Messages are fixed safe copy; `request_id` is opaque. Reads may retry once on a
transient network failure; writes never automatically retry without a jointly
approved idempotency contract. Browser-supplied roles/owner IDs grant no authority.

## Endpoints and data shapes

All response fields below are required unless marked `?`; nullable values remain
present as JSON null. Mutating success status is specified per row.

| Endpoint | Request | Response / rule |
|---|---|---|
| `GET /health` | none | 200 `{status: "ok" | "degraded", api_version: "v1"}`; no infrastructure secrets |
| `POST /sessions` | `{}` | 201 `Session`; establish server-bound anonymous local-demo owner |
| `GET /sessions/{session_id}` | owner credential | 200 `Session`; foreign/unknown => same 404 |
| `GET /sessions/{session_id}/messages?cursor=&limit=` | owner credential | 200 `{items: Message[], next_cursor: string|null}`; stable chronological pages |
| `DELETE /sessions/{session_id}` | owner credential + CSRF control | 204; delete owned messages and feedback in transaction |
| `POST /chat` | `{session_id, message}` | 200 `ChatResponse`; transactionally persist owned synthetic-demo turn |
| `GET /resources?q=&limit=` | public read | 200 `{items: Resource[]}`; approved ordinary-chat eligibility only |
| `POST /feedback` | `{session_id, message_id, rating: "helpful" | "not_helpful"}` | 201 `Feedback`; message must be assistant turn in owned session |

`Session = {id, created_at, updated_at}`. No token/hash/owner identifier in JSON.
`Message = {id, session_id, role: "user" | "assistant", text, created_at,
citations: Citation[], safety_lane: SafetyLane|null}`.
`Feedback = {id, session_id, message_id, rating, created_at}`.
Duplicate feedback for one owner/message updates the existing rating and returns
200; first creation returns 201. No free-text feedback in this wave.

`ChatResponse = {session_id, message: Message, response_type, safety_lane,
is_terminal_safety, citations: Citation[], clarification: Clarification|null}`.
`response_type = "safety" | "answer" | "clarification" | "alternatives" | "fallback"`.
`SafetyLane = "urgent_safety" | "title_ix" | "harassment_hate"`.
Only the trusted backend maps dispatcher/router outcomes to safety fields;
neither a model nor the frontend infers them by matching generated prose.
Existing `Dispatcher.respond()` remains `{text, trace}`. Any adapter need for
additional metadata must be jointly agreed; do not silently re-route or redesign
the dispatcher. Final response text for a recognized safety lane equals its
deterministic template, `is_terminal_safety=true`, citations empty and clarification
null. Safety response generation is independent of ordinary retrieval.

`Clarification = {prompt, options: {id, label}[]}`; IDs are bounded server-defined
choices and never tool names or executable payloads. A selected option produces
a new user turn, which passes through original-input safety routing again.

`Citation = {source_id, chunk_id, title, url, version, approved_at, checked_at}`.
`Resource = {id, title, url, category, provenance: Provenance}`.
`Provenance = {source_id, version, content_sha256, fetched_at, approved_at,
approved_by, checked_at, expires_at}`. Approval principals are server-owned IDs;
client/source text cannot assert approval. Display source evidence accessibly.
Only validated HTTPS approved-source URLs become clickable links.

## SQLite, ownership and privacy

Devika owns migrations and repositories; Abhinav mounts their routes and supplies
the shared authorization context. Use foreign keys, parameterized SQL, transactions
and an explicit schema version. Proposed tables:

| Table | Columns and constraints |
|---|---|
| `schema_migrations` | version primary key, applied_at |
| `owners` | id primary key, credential_hash unique, created_at, expires_at |
| `sessions` | id primary key, owner_id FK owners, created_at, updated_at |
| `messages` | id primary key, session_id FK sessions on delete cascade, role check, text, citations_json, safety_lane nullable, created_at |
| `feedback` | id primary key, session_id FK sessions on delete cascade, message_id FK messages on delete cascade, rating check, created_at; unique message_id |

Repository operations always bind server-derived owner ID and session ID in the
same query. Feedback verifies message/session membership and assistant role inside
the transaction. Index sessions by owner, messages by session/time/id. Local DB
path comes from configuration, remains ignored and is never committed. Failed
writes roll back; partial chat turns are not represented as successful persistence.

Candidate pre-auth local-demo ownership: server-generated 32-byte random owner
credential, hash stored in SQLite, HttpOnly SameSite=Strict cookie, Secure except
explicit loopback HTTP development. Mutating routes require server Origin checks
and a session-bound CSRF token under the agreed adapter. CORS is an exact local
origin allowlist; no wildcard credentialed CORS. This establishes anonymous session
ownership only; it grants no administrative permissions. Abhinav must approve and
own the future authenticated principal/RBAC integration, including safe migration.
Until then administrative APIs/actions are disabled server-side.

Use synthetic demonstrations only. Persisted conversation text is excluded from
logs and remote telemetry. Proposed expiry is 24 hours, purged on server startup
and explicit owner deletion; expiration behavior and deletion tests must be agreed.
Do not deploy for real student records or public clinical use.

## Governed retrieval and bounded tools

Devika's proposed new ingestion/governance modules are additive; preserve the C1
`retrieve(query, k=3, top_k=None)` API and eligible ranking behavior. Approval metadata
is versioned separately from legacy JSONL until a jointly approved migration lands.
Eligibility requires source allowlist, explicit approval, valid provenance/version,
unexpired review and ordinary-chat permission. Continue excluding `allow_chat:false`
and `page_type:crisis` before ranking. Missing/invalid governance fails closed.

Ingestion accepts approved public HTTPS sources only, with bounded response size,
content types and fetch duration. Validate every redirect and resolved address;
deny private/link-local/loopback destinations, credentials and unapproved hosts.
No live network required in tests. Retrieved instructions remain untrusted content.

Candidate tool `retrieve_resources` input `{query, limit}`; output
`{status: "ok" | "empty" | "unavailable", items: Resource[], citations: Citation[]}`.
Registry validates schema and server authorization before execution; unknown tools,
unknown arguments and denied resources fail closed. No tool can mutate permissions,
approve sources or change a safety decision. Abhinav owns the registry, budgets
and execution authorization; Devika owns this handler's retrieval/citation checks.
Agree exact call/time/result budgets before implementation. Citation integrity is
checked against the returned eligible chunks, never manufactured from model text.
Empty/unavailable results use grounded fallback copy without invented guidance.

## Frontend and verification gates

React + TypeScript + Vite, npm with committed `package-lock.json`, same-origin `/api`
in deployed builds. Local frontend port 5173, backend loopback port 8000, Vite dev
proxy to backend. Typed API client centralizes credentials/errors and exposes only
the approved schema. UI handles loading, cancellation, errors, clarification,
citations and distinct deterministic safety presentation; keyboard/screen-reader
navigation, responsive layouts and plain text rendering are required. Never render
retrieved HTML or treat hiding a button as authorization.

Observed local tools: Node 24.17.0, npm 11.13.0. These are candidate pins, not an
approved cross-platform support claim. Both humans must confirm exact Node/npm,
React/TypeScript/Vite/test-runner versions, Python dependency lock approach and
CI ownership before any dependency or lockfile is added. No paid provider needed.

Proposed checks: frontend type/lint/component/build; offline FastAPI contract tests;
SQLite migration/rollback/deletion and cross-owner isolation; forged owner/role,
CSRF and unauthorized admin denial; poisoned/stale/unapproved-source exclusion;
citation mismatch and retrieval-outage fallback; deterministic safety precedence
through the API; end-to-end student session/chat/citations/feedback workflow.
Lexical-versus-local-hybrid benchmark uses the same frozen synthetic queries and
approved corpus, reports actual quality/latency, and documents unavailable optional
dependencies. Jointly add gates to existing CI rather than creating competing CI.
